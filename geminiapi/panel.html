GeminiAPI

provider geminiapi · 命名空间 ai-studio, gemini-web · 版本 —

访问口令

页面通过 CPA 的 /v0/management 接口访问插件，口令只保存在这个标签页的内存里，不写 localStorage。

两套后端

本插件托管两个互不相干的后端：ai-studio 用 AIStudio2API 0.3.5-magpie.1， gemini-web 用 gemini-web2api-go 4.28.0-magpie.1。两套独立的 pin、独立的数据目录、独立端口、 独立 pid 文件与独立进程组；一个挂了不影响另一个，模型也各自发布在自己的命名空间前缀下。

后端控制未选择

后端是插件托管的本机进程：首次启动会下载 pin 版本的二进制并做 sha256 校验（AI Studio 的资产是压缩包， 要先校验压缩包、再校验解包出的可执行文件），校验不通过绝不启动。它只监听 127.0.0.1； 停止时按进程组回收，CPA 退出时插件会停掉它，避免遗留孤儿进程占住端口。

账号

gemini-web：导入 Cookie

gemini-web2api-go 自己持有 Google Cookie。推荐流程：用无痕窗口（Firefox 或 Chrome）登录 gemini.google.com 并打开 F12 → Network → 刷新 → 点任意 gemini.google.com 请求 → Request Headers 里复制 cookie 那一行的完整值，粘贴到下面。Cookie 只会写进本地后端自己的数据库， 不写进 CPA 配置、不写进日志、也不会出现在任何响应里。后端会定时刷新登录态，所以请不要在你平时登录着 Google 的窗口里复制，否则浏览器会被踢出登录。

ai-studio：浏览器登录

AIStudio2API 不接受粘贴的 Cookie：它用自带浏览器完成 Google 登录，并把授权状态存在 自己的数据目录里。点下面的按钮会让它在它自己的窗口里开始登录；登录完成后刷新账号数即可。 插件全程不接触任何 Google 凭据。
